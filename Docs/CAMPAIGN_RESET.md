# New Game / Campaign Reset

The New Game command resets only OEM campaign state. It must never delete Orbiter
scenario files, vessel configuration, SDK data, module settings, or the derived
surface-spaceport catalogue.

## Campaign state

The reset boundary includes:

- the global economy journal and its replayed company balance/trade history;
- the flight/docking event journal;
- per-location opening stock files generated by OEM;
- vessel cargo manifests and legacy cargo exchange journals, if present;
- contract and mission persistence introduced by later milestones;
- player-created economic station registrations and cargo-service permissions.

After reset, the company balance is loaded again from the configured opening
account definition. The cargo catalogue and module preferences remain available.
Newly encountered station and spaceport inventories start empty; reset must not
synthesize cargo.

## Preserved data

- `accounts.cfg`: opening company account definitions;
- `cargo_catalog.cfg`: item definitions, masses and prices;
- `spaceports.registry`: derived Orbiter base/pad catalogue, rebuilt at scenario start;
- module and interface settings;
- all files outside OEM's explicit campaign-file allowlist.

`economic_stations.registry` stores the player's explicit station identities, and
`cargo_services.cfg` stores the independent cargo-service permissions. Both are
maintained by the OEM Economic Admin MFD and both are campaign state; a New Game
must clear both.

## Safety requirements for native implementation

1. Require an explicit second confirmation in the MFD.
2. Disable the command while a journal write or economy operation is in progress.
3. Enumerate only direct children of `OEMData`; never recurse into arbitrary folders.
4. Delete only filenames accepted by `CampaignResetPolicy`.
5. Stage the complete deletion set before committing the reset. If staging fails,
   roll back all staged moves and leave the current campaign active.
6. Clear in-memory projections only after the persistence transition succeeds.
7. Reinitialize from preserved opening account/catalogue configuration.
8. Report a failure instead of claiming success if any owned file cannot be safely
   removed. Never touch Orbiter scenario state.

`CampaignResetPolicy` is the portable, unit-tested allowlist used by the native
implementation. It classifies filenames only; it does not perform filesystem I/O.
